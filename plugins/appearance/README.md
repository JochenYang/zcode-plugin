# appearance

给 ZCode 桌面端换自定义背景和配色皮肤：图片或视频可以铺满整个窗口，图片也可以只画在会话区；上面压一层主题色的遮罩保证文字可读，可以模糊，可以多个定时轮换。在侧边栏的面板里拖滑块即时生效，也可以用 `/appearance` 在对话里改。零 npm 依赖。

> 第一版。真机上验证到哪一步见文末「验证情况」。

## 它由三部分组成

ZCode 的插件接口碰不到应用自己的外壳：插件只能出现在沙箱页面和几类入口里，没有「改应用样式」的贡献点。应用外观的另一个入口是它的调试通道（`--remote-debugging-port`），而它只在进程启动时打开，并且应用是单实例：已经有一个实例在运行时，新启动的那个会把控制权交出去然后退出。

| 部分 | 做什么 | 在哪运行 |
|---|---|---|
| 启动器 | 带调试通道启动 ZCode，把样式注入每个窗口，盯着配置文件 | ZCode 外部的一个 Node 进程（`bin/launch.mjs`） |
| MCP server | 给模型两个工具，在对话里读写配置 | ZCode 的 MCP 进程（`bin/server.mjs`） |
| 扩展 | 侧边栏的面板：每个设置是一个控件，改了就生效 | ZCode 的扩展进程（`bin/extension.mjs`）+ 沙箱里的页面（`ui/index.html`） |

从原来的快捷方式启动 ZCode，得到的就是不带背景的原版。

## 快速开始

需要 Node 22 或更新版本（用到内置的 WebSocket）。下面以本仓库的路径为例。

1. **完全退出 ZCode**，托盘图标里也要退出。
2. 安装并启用本插件，然后启动：

   ```bash
   node plugins/appearance/bin/launch.mjs
   ```

   ZCode 起来后启动器留在后台。日常使用时有两种启动方式：
   - 双击 `plugins/appearance/zcode-appearance.cmd`（可以给它建个快捷方式）：不留控制台窗口，出错时弹一个消息框，图标是 cmd 的。
   - 做一个带 ZCode 图标、名称自己定的启动器程序，固定到任务栏 / 程序坞 / 应用列表：见下一节。
3. 改设置，三种方式任选：
   - **面板**：侧边栏的「扩展」里点「外观」。第一次打开时 ZCode 会问是否启用这个扩展，启用后要完全退出应用再打开一次，入口才出现。
   - **对话**：`/appearance 只换会话区，遮罩 0.7`。
   - **配置文件**：`node plugins/appearance/bin/launch.mjs --edit`，保存即生效。

## 启动器程序（任务栏、程序坞、应用列表）

一条命令，按所在系统各做各的：Windows 用系统自带的 C# 编译器现编译一个 exe，macOS 拼一个 `.app`，Linux 放一个启动脚本并在应用列表里加条目。三个系统都不用装任何东西；Windows 的编译只要两秒左右。仓库里不放编译好的二进制，也不放 Z.AI 的图标（图标在生成时从本机装的 ZCode 里取）。

**装好插件之后最省事的做法：在对话里跟 ZCode 说「帮我做外观的启动器」。** `get_appearance` 的回答里带着这条命令在本机的完整路径（安装副本在一个按版本号命名的目录里，不好猜），模型照着运行就行。

自己运行的话，路径按插件在哪来写：

| 插件在哪 | 命令 |
|---|---|
| 这个仓库里 | `node plugins/appearance/bin/setup-launcher.mjs` |
| 已经装进 ZCode | `node "<ZCode 数据目录>\cli\plugins\cache\<市场>\<插件>\<版本>\bin\setup-launcher.mjs"`（Windows 的数据目录默认是 `%USERPROFILE%\.zcode`；具体路径以 `get_appearance` 给的为准） |

```bash
node plugins/appearance/bin/setup-launcher.mjs                      # 名称默认 "ZCode Appearance"
node plugins/appearance/bin/setup-launcher.mjs --name "我的 ZCode"   # 换一个名称
node plugins/appearance/bin/setup-launcher.mjs --uninstall          # 撤销
```

| 系统 | 做出来的东西 | 怎么固定 |
|---|---|---|
| Windows | `<LocalAppData>\<名称>\<名称>.exe`（用系统自带的 C# 编译器现编译）和开始菜单里的快捷方式 | 开始菜单里右键 →「固定到任务栏」 |
| macOS | `~/Applications/<名称>.app`（一个 `.app` 包，里面的程序是 `launcher/launcher.sh`） | 访达里把 `.app` 拖到程序坞 |
| Linux | `~/.local/opt/<名称>/` 里的启动脚本，和应用列表里的条目（`.desktop`） | 应用列表里右键 → 添加到收藏 / 固定到任务栏，看桌面环境 |

- **图标**在生成时从本机已安装的 ZCode 里取：Windows 把 `resources\icon_windows.png` 做成四个尺寸的 `.ico`，macOS 直接用 `ZCode.app` 里的 `.icns`，Linux 复制 `resources/icon.png`。所以仓库里既没有二进制，也没有 Z.AI 的图标。
- **ZCode 在哪不用填**。启动器和这条命令按同一个顺序找：配置里的 `launcher.zcodePath` → 环境变量 `ZCODE_APPEARANCE_EXE` → 正在运行的 ZCode → 常见目录（`%LOCALAPPDATA%`、各盘的 `Program Files\ZCode`）→ 系统的安装记录（Windows 登记表里的卸载条目，装在哪个盘、哪个目录都有）。常见目录排在前面是启动提速的一环（省一次 PowerShell 的 1.5 秒）；Program Files 里留着旧版、新版装在别处时它会起旧版，那时在配置里写 `launcher.zcodePath`。都没有时用 `--zcode <路径>`。
- **`--link`（默认）** 只记下 `bin/launch.mjs` 的位置，始终用这个插件目录里的代码；插件被移走或换到别的版本目录后要重新运行一次。**`--copy`** 把启动器自己的文件复制进去，之后不受插件目录变动影响，但插件更新后也要重新运行一次才用上新代码。
- 这个程序只负责拉起启动器然后退出。ZCode 的窗口仍然归在官方 ZCode 的任务栏图标 / 程序坞图标下，启动器是单独的一项。三个系统都不允许程序替用户做「固定」这一步，留给人拖一下或右键一下。
- 程序需要 Node 22 或更新版本，并且找得到 `node`。macOS 和 Linux 从程序坞或应用列表启动时拿到的是系统的 PATH，脚本会在 Homebrew、nvm、volta、fnm 的常见位置自己找；也可以用环境变量 `ZCODE_APPEARANCE_NODE` 指定一个。找不到 node、找不到启动脚本时，程序退出码为 1，在自己旁边写 `launcher-error.log`，并弹一个提示。
- `--dir <目录>` 改放置位置，`--no-shortcut` 不建快捷方式 / 条目。`--dir` 要给一个**专用目录**：新的、空的，或者上次放过启动器的；里面已经有别的东西时这条命令会拒绝，因为 `--uninstall` 会把目录一起删掉。卸载只删它自己写出来的文件，目录里后来又放了别的，目录就留着。

## 命令

| 命令 | 作用 |
|---|---|
| `node bin/launch.mjs` | 完全退出 ZCode 后运行：启动 ZCode 并注入，然后留在后台 |
| `--edit` | 用系统默认程序打开配置文件（没有就先建一份） |
| `--status` | 显示当前配置、启动器和 ZCode 是否在运行 |
| `--attach[=端口]` | 不启动 ZCode，接管一个已经带着调试通道运行的实例；端口省略时读启动器留下的状态文件，再不行用配置里的 |
| `--once` | 注入一次就退出，不留在后台 |
| `--config <文件>` | 用另一份配置文件 |
| `--verbose` | 日志同时打到屏幕上（始终写入 `~/.zcode/appearance/launcher.log`） |

## 面板

侧边栏「扩展」里的「外观」。每个控件改了就生效，没有「保存」按钮。

| 区块 | 控件 |
|---|---|
| 背景 | 开关；整页 / 只换会话区；遮罩、模糊两个滑块；轮换间隔 |
| 图片和视频 | 列表（文件名、是图片还是视频、找不到的会标出来、排在第一位的那个有标记、每个都能移除）；填路径添加，或者用系统的文件选择框添加。列表的顺序就是轮换的顺序，不轮换时显示排在第一位的：多个文件时每一行可以上移、下移，也可以整行拖到别的位置；不轮换时其余每一行还有「显示这一项」，一下就把它放到第一位 |
| 配色皮肤 | 预设卡片（每张上有浅色、深色两行色块）、「自定义」展开十个颜色选择器，浅色、深色各五个；选回「默认」或别的预设时，自定义的颜色留着不丢，再点「自定义」就回来 |
| 其它 | 打开配置文件；恢复默认设置（先问一句，图片和视频保留） |

启动器不在运行时，面板会说明改动已保存、下次从启动器启动 ZCode 时生效。

面板的文字跟随应用的语言（设置里的界面语言），每次回答都向应用问一次，所以中途改了语言，下一次操作就是新的；应用给不出时退回系统语言，再不行是英文。

## 配置文件

`~/.zcode/appearance/config.json`。保存即生效，不用重启 ZCode。

```json
{
  "background": {
    "enabled": true,
    "media": ["E:/Wallpaper-Polling/littlejochen.png"],
    "scope": "page",
    "rotateMinutes": 0,
    "mask": 0.72,
    "blur": 0
  },
  "skin": {
    "preset": "default",
    "custom": null
  },
  "launcher": {
    "zcodePath": null,
    "port": 9337
  }
}
```

| 键 | 取值 | 说明 |
|---|---|---|
| `background.enabled` | `true` / `false` | 关掉背景但保留设置 |
| `background.media` | 文件路径数组 | 图片：png、jpg、jpeg、webp、gif、bmp、avif，单个不超过 20 MB；视频：mp4、webm。相对路径按用户主目录解析（启动器以主目录为工作目录），建议写绝对路径。只收本地文件：网络路径（`\\主机\共享\…`）会被拒绝，读它等于让 Windows 拿你的凭据去连那台机器；要用的先把共享映射成盘符 |
| `background.scope` | `page` / `chat` | `page` 整页，`chat` 只换会话区（只有图片可以） |
| `background.rotateMinutes` | 整数 | 每隔多少分钟换下一个，`0` 为不轮换，最大 525600（一年） |
| `background.mask` | 0 到 1 | 压在背景上的主题色遮罩，越大文字越清楚；花哨的图 0.7 左右，素净的图 0.3 左右 |
| `background.blur` | 0 到 40 | 背景模糊的像素值，仅 `page` 有效 |
| `skin.preset` | `default`、十个内置预设之一，或 `custom` | 配色皮肤，见下；`custom` 用的是 `skin.custom` 里的颜色 |
| `skin.custom` | 对象或 `null` | 自己的皮肤，见下；只在 `skin.preset` 是 `custom` 时生效，选别的预设时留着 |
| `launcher.zcodePath` | 路径或 `null` | ZCode 可执行文件；`null` 时自动找（顺序见「启动器程序」一节），写错了会直接报错而不是悄悄去找别的 |
| `launcher.port` | 端口 | 调试通道的起始端口（1 到 65535），被占用时自动往后找 |

环境变量 `ZCODE_APPEARANCE_EXE` 优先于 `launcher.zcodePath`，两者都没有时才去找。

## 两种范围

**`page`（整页）**：图片作为一层固定的背景铺在最底层，上面一层是遮罩；应用的底色、侧栏底色和窗口自己那层底色改成透明，其余表面（卡片、弹层、输入框）保持不透明。视频在同一个位置放一个 `<video>` 元素，静音、循环、铺满，窗口不可见时暂停。

**`chat`（只换会话区）**：图片画在会话卡片上，就是应用自己标记为 `data-testid="conversation"` 的那一块里带圆角和边框的卡片；卡片原本用应用底色填满，在会话区里这个底色改成透明，图才露出来（第一版把图画在卡片外面，被它整个盖住，看起来像没生效）。遮罩是卡片里单独的一层，压在图上、在文字下面。滚动时图片不动，会话内容从上面滚过。窗口其它部分保持原样。这个模式不支持视频，也不支持模糊：轮换到视频的那一项时不显示背景，启动器在日志里记一次 `video-needs-page`。

图片是以数据地址写进样式的，一张照片有两三兆。写法上有一条限制：图片那条声明里不能同时出现 CSS 变量，否则 Chromium 会把整条声明丢掉（小图不会，测试里用的是一像素的图，所以直到在真机上用你自己的壁纸才发现）；现在图片和遮罩分成两条声明。

遮罩的颜色取自当前主题的底色：注入时从应用里读出来，明暗切换时重读，所以深色主题下是深色遮罩。强度在两个主题下是同一个数值：试过让浅色主题自动加强 18 个百分点，结果图几乎看不见了，比个别地方文字难读更糟，所以没有这样做。浅色主题下觉得文字不清楚，直接把遮罩拉高一点。

## 配色皮肤

ZCode 的界面颜色都来自 `--color-*` 变量。一套皮肤给出浅色、深色各五个颜色，工具据此替换底色、卡片、文字、强调色、边框这几个变量；应用自己从这几个派生的那些——次级按钮（比如生成时输入框的停止按钮）、悬停背景、悬停边框、次级文字、输入框、头部、选中的卡片、主按钮——也按应用自己主题里的比例从这五个颜色调出来，所以换皮肤不会有哪块还留着原主题的颜色。

- `default`：保持应用原色。
- 内置十套，每套取自一套很多人天天在用的配色方案——编辑器主题里装得最多的那几套，加上 Twitch、Discord、GitHub 这几个应用的配色——所以看起来是「那个味道」，不是五个颜色拼起来的。方案自己的强调色或文字若在 ZCode 的表面上不到 4.5:1，就取同一色相里最近的一档：

  | 预设 | 取自 | 浅色 | 深色 |
  |---|---|---|---|
  | `catppuccin` | Catppuccin | Latte（卡片比窗口亮一档，强调色是 mauve） | Mocha |
  | `kanagawa` | Kanagawa（北斋配色） | Lotus，蓝色深一档 | Wave |
  | `ayu` | Ayu | Light，强调色是按钮上那种橙的深档 | Dark，橙 |
  | `one-dark` | Atom One Light / One Dark Pro | Light，蓝色深一档 | Dark Pro |
  | `nightfox` | Nightfox | Dayfox | Nightfox |
  | `discord` | Discord | 浅灰 + 深一档的 blurple | 深灰 + 蓝 |
  | `sakura` | Rosé Pine | Rosé Pine Dawn | Rosé Pine，强调色是它的 love |
  | `amber` | Gruvbox | 浅色，橙色 | 深色，亮橙 |
  | `plum` | Twitch | 浅灰 + Twitch 紫 | 深灰 + 浅紫 |
  | `graphite` | GitHub | 浅色，唯一的蓝 | 深色 |

  每套的文字和强调色在底色、卡片色上都量过对比度，不低于 4.5:1，边框在底色上看得见——`tests/skins.test.mjs` 会一直查。
- `custom`：自己的皮肤。在面板里点「自定义」，十个颜色选择器；也可以直接写，每个模式五个十六进制颜色，可以只给其中一个模式。它和别的预设并列：选回「默认」就是应用原色，自定义的颜色留着不丢，再点「自定义」就回来。从 0.1.1 升级上来的人注意：旧版里「默认 + 一套自定义颜色」是生效的，现在要选「自定义」才用那套颜色（`get_appearance` 的回答里会提示它留着没用上）。

  ```json
  "skin": {
    "preset": "default",
    "custom": {
      "dark": { "base": "#101418", "surface": "#181d25", "text": "#e6e6e6", "accent": "#38bdf8", "border": "#2a303a" }
    }
  }
  ```

背景开着且范围是整页时，底色和侧栏仍然是透明的，皮肤只影响遮罩的颜色和其它表面。

## 斜杠命令

`/appearance [要求]`。不带参数显示当前设置；带要求时由模型改成工具字段。

```text
/appearance
/appearance 背景换成 E:\Wallpapers\a.jpg
/appearance 只换会话区，遮罩 0.7
/appearance 整页，模糊 4，每 30 分钟换一个，再加上 D:\Clips\b.mp4
/appearance 把第二个去掉
/appearance 关掉背景
/appearance 换成 catppuccin 皮肤
```

模型看到的工具是 `mcp__plugin_appearance_style__get_appearance` 和 `mcp__plugin_appearance_style__set_appearance`。它们只读写配置文件，校验每一次改动并拒绝不认识的字段，不碰 ZCode。

## 工作原理

- **启动**：确认 ZCode 没在运行（Windows 上用 `tasklist`，百毫秒以内；PowerShell 要一秒半）、找到它的可执行文件（配置 → 环境变量 → 正在运行的进程 → 常见目录 → Windows 登记表里的卸载条目，第一个存在的为准；登记表那一问要起一次 PowerShell，排在最后，装在常见位置时根本问不到）、找一个空闲端口，以 `--remote-debugging-port=<端口>` 启动它，每 100 毫秒探一次调试通道。通道一应答就开始，不再固定等一段时间。日志里记着通道多少毫秒后应答、首个窗口启动后多少毫秒拿到样式（`~/.zcode/appearance/launcher.log`）。
- **注入**：首个窗口拿到样式之前，循环每 100 毫秒看一次（窗口总比通道晚一点出现，等满一个两秒的间隔曾占去背景出现时间的大半）；之后每两秒列一次应用的窗口，对每个窗口做三件事：登记一段脚本，让页面重载时在任何页面代码之前先运行；问一句「现在显示的是不是这一份样式」；不是才发送完整样式。样式里带着图片，所以平时只发那一句短问题。启动的 ZCode 若没等到任何窗口就退出了（单实例把控制权交了出去），启动器把原因说明白再退出。
- **变了才读**：启动器监听配置文件所在的目录（文件是先写临时文件再改名写入的，所以要监听目录），变了就重读、重新生成，并立刻唤醒上面的循环，不等下一个两秒。每 30 秒另外核对一次两个文件的时间，防的是监听漏掉事件。文件写坏了就沿用上一份有效的设置，并在日志里说一次。
- **样式怎么进页面**：打包版的主窗口是从 `app.asar` 里的 `file://` 地址加载的（真机上看到的），页面自己没有 CSP，注入的 `<style>` 直接生效。图片仍然转成 `data:` URL 写在样式里：页面不需要任何路径访问。视频交给页面一个 `file://` 地址，由 `<video>` 元素自己读（真机上验证过能播放）。
- **整页为什么要改三个变量**：窗口里画底色的地方有三处：根容器的 `bg-background-win-alt`（Windows 专用底色）、通用底色 `bg-background`、侧栏 `bg-sidebar`。第一版漏了第一个，结果只有启动画面能看到图。这三处变透明要等页面脚本确认三件事之后才发生（`<html>` 上的 `za-shown`）：应用的颜色（遮罩从它配）、应用的主题 class、图片解码完成。样式是在页面开始约 350 毫秒时注入的，那时应用还没说出主题，立刻透明会先画一层浅色主题的遮罩——一启动就闪一下白屏。三件事各有一个兜底时限：主题最多等 4 秒（应用是在设置加载后才把主题 class 切上去的，真机上比样式晚一到两秒；等不到就放行会先按浅色遮罩显示一下再变深）、图片 3 秒、颜色 5 秒，到时间就按回退值显示（所以应用哪天改了名字，表现是「晚几秒出图」而不是「永远不出图」）。
- **只认应用自己的页面**：启动器只跟应用自己的页面打交道，从网络地址（http、https）加载的页面和 DevTools 一律不碰——样式里带着你的图片，登录页、授权页不该拿到它。入口页把应用挂在 `#root` 里，插件的沙箱页面和工具窗口没有它；脚本等到 `#root` 出现才动手，等 10 秒还没有就不再打扰那个页面（之后每秒看一眼，应用挂载晚了照样补上），不会隔一阵把整份样式重发一遍。
- **跟随主题**：盯着 `<html>` 和 `<body>` 的 `class`，主题一变就重读应用的底色、重画样式。
- **面板的图标**：Lucide 的图形（ISC）直接画在每个图标里，不用 `<use>` 去引用一张隐藏的图形表：在应用的沙箱里那种引用偶尔是一片空白，直到页面重绘。
- **启动画面的 logo**：应用自己的启动画面（深色圆角壳里的 logo）本来就有一个 0.72 秒的弹出，这个弹出原样保留（样式是在页面开始约 350 毫秒后注入的，改写它的动画会让弹出重放一次）。显示背景时，logo 轻轻呼吸（`transform` 缩放，由合成器驱动：启动画面在屏幕上的那 0.6 秒里主线程被应用自己的脚本占满，主线程上的动画会原地不动），启动画面淡出从 0.16 秒放宽到 0.36 秒、首屏淡入 0.3 秒。系统开了「减少动态效果」时不加。沿边框跑的亮光试过两版，在真机的启动阶段都没能稳定显示，已移除。
- **面板怎么改到窗口**：面板里的控件调用扩展进程的工具（读、改、添加、移除、选文件、恢复默认、打开配置），工具写配置文件，启动器发现文件变了就注入。扩展进程不直接碰窗口，所以写样式的只有启动器一个，不会有两个版本打架。
- **文件选择框**：扩展进程起一个 PowerShell 的 Windows Forms 打开文件对话框（多选，只列图片和视频），它关闭后把选中的文件写进配置。对话框想开多久就开多久：工具立刻回答「已经打开」，面板每 400 毫秒问一次结果。Windows 上它打开在列表里第一个还在的文件所在的文件夹；选中的路径以 base64 传回来（按文字写出来的话，中文目录名会按控制台编码出来、变成乱码，第一版就是这样把一个视频的路径存坏的），进程从用户主目录启动、并补上 Windows 外壳要的环境变量（缺 `SystemDrive` 时它会把缓存建到一个字面叫 `%SystemDrive%` 的目录里）。macOS 用 `osascript`，Linux 用 `zenity`；没有的可用的就提示改填路径。
- **改样式不用重启**：`src/css.mjs` 所在的目录同样被监听，变了就重新加载它。只覆盖这个文件本身；它引用的皮肤（`skins.mjs`）和校验（`config.mjs`）还是启动器启动时那一份。

## 安全

- **调试通道没有鉴权**。ZCode 带着通道运行期间，本机任何进程都能连上去、在 ZCode 的页面里执行脚本。只适合个人电脑；不要在带着通道运行时让不信任的程序进来。Windows 的回环地址是整台机器共用的：多用户的机器上（快速切换、远程桌面），别的标准用户也能连上这个端口。
- 通道只监听 `127.0.0.1`。
- 启动器不安装任何东西，不改 ZCode 的文件；它写入的只有自己那个文件夹 `~/.zcode/appearance/` 里的 `config.json`、`launcher.log` 和运行期间的 `status.json`（0.2.0 之前这三个文件散在 `~/.zcode` 下，第一次启动时自动挪进文件夹）。`setup-launcher.mjs` 另外写入自己的一个目录和开始菜单 / 应用列表里的一项，`--uninstall` 只删它自己做出来的东西。
- MCP 工具和面板的工具只读写配置文件。图片路径由启动器读取并转成 `data:` URL，只接受上表列出的图片扩展名；视频路径变成 `file:` 地址交给页面，也只接受上表列出的视频扩展名。面板里填的路径必须是完整路径。
- **不要手动结束启动器进程**。2026-11-27 结束它之后 ZCode 跟着退出、正在进行的会话被打断（原因没有查清：可能是子进程随它一起结束，也可能是那个进程号已被 ZCode 的某个组件复用）。要停背景，改配置里的 `background.enabled`，或者正常退出 ZCode。

## 已知限制

- 只改外观，不加功能。
- ZCode 自动更新后自己重启时不带通道，背景会消失；从启动器再启动一次就回来。
- 依赖应用内部的几处名字：会话区的 `data-testid="conversation"`、根容器的底色变量、`--color-*` 变量。版本更新改掉它们时样式要跟着改；找不到会话区时启动器会在日志里记 `missing-root`，而不是假装成功。
- 冷启动到注入完成之间的第一帧是原样。
- 皮肤只替换了主要变量，个别写死的颜色（个别状态色、图标）不跟着变。
- 视频一直在解码：一个 1080p 的循环视频会持续占用一些显卡或处理器，窗口最小化或被完全遮住时暂停。
- 文件选择框和自定义颜色选择器里的系统取色窗口，在 ZCode 的沙箱里能否正常弹出，取决于这台机器上的实际效果（见「验证情况」）。

## 排障

| 现象 | 原因与处理 |
|---|---|
| 提示 ZCode 已经在运行 | 完全退出它（托盘里也要），再从启动器启动 |
| 没找到 ZCode 的可执行文件 | 在配置里把 `launcher.zcodePath` 写成完整路径，或设置 `ZCODE_APPEARANCE_EXE` |
| 启动器程序点了没反应 | 看程序旁边的 `launcher-error.log`：多半是找不到 node（要 22 或更新版本，并且在 PATH 里；macOS / Linux 可设 `ZCODE_APPEARANCE_NODE`），或者插件目录被移走了（重新运行一次 `setup-launcher.mjs`） |
| 启动后 ZCode 马上退出 | 还有实例没完全退出，新启动的那个把控制权交给了它 |
| 背景没出现 | `--status` 看配置；`~/.zcode/appearance/launcher.log` 看启动器说了什么（`missing-root`、`video-needs-page`、文件读不到、调试通道没应答） |
| 改了配置没变化 | 确认启动器还在运行（`--status`）；面板会直接说明这一点 |
| 侧边栏里没有「外观」 | 插件是否启用；扩展第一次启用后要完全退出应用再打开 |
| 文字看不清 | 调高遮罩 |
| 只有启动画面有图，进入界面后没有 | 应用又多了一处画底色的地方（4.0.10870 上是根容器的 `--color-background-win-alt`）。按 `--attach` 连上调试通道，从页面中央往上找第一个带不透明底色的元素，把它的变量加进 `src/css.mjs` 的透明规则 |
| 换成会话区后没有图 | 看 `~/.zcode/appearance/launcher.log`：有 `missing-root` 是这个版本的 ZCode 改了会话区的标记；没有的话，用 `--attach` 连上调试通道，看 `[data-testid="conversation"]` 里面那张带 `bg-background` 的卡片有没有算出 `background-image` |
| 面板里加不了文件 | 填的要是完整路径；选择框弹不出来时直接填路径 |
| 选完文件却显示「找不到这个文件」 | 0.2.0 之前选中的路径里若有中文，存进配置的就是乱码；删掉那一行重新选一次。手动填路径不受影响 |

node --test plugins/appearance/tests/

- 配置校验、样式生成、MCP 协议（含真实进程上的握手与调用）、启动器的参数与状态文件。
- 启动器的设置读取：用替身和真实的目录监听各验一遍「不变不读、变了才读、写坏了沿用上一份」。
- 扩展进程：假宿主驱动真实的 `activate`，七个工具逐个对着真实的配置文件跑，文件对话框用注入的替身。
- 启动器程序：Windows 上用系统自带的 C# 编译器真实编译并运行（名称与描述、四个尺寸的图标、拉起 node 的方式、出错时的退出码与日志）；macOS 与 Linux 的布局在把平台切换后生成并逐个文件核对；桩脚本 `launcher/launcher.sh` 在 POSIX sh 下按 `.app` 与平铺两种布局真实运行。ZCode 的查找用注入的命令输出验三种来源的先后。

## 验证情况

- **无头 Chromium**：全部通过（见「测试」）；设计技能的 `audit.mjs` 在 760 与 390 像素、浅色与深色下必须修的项为 0。
- **真实 ZCode 4.0.10870，Windows，2026-11-27**：
  - 打包版接受 `--remote-debugging-port`，启动器把样式送进了主窗口（日志 `applied`）。
  - 第一版在真机上暴露了三个无头测试没拦住的问题，都已修掉并补了断言：两个背景层的选择器漏了 `#`；遮罩变量挂在根元素上、读不到应用写在 `body` 上的底色；漏了根容器的 `--color-background-win-alt`，图只在启动画面可见。
  - 修掉之后按页面里的计算结果核对过：背景层固定铺满整个窗口、图片在样式里、遮罩是应用底色 `#161616` 的 72%；把窗口按 8×6 的网格采样，不透明的只剩输入框和内容卡片。
  - 真实的目录监听：配置写入后约 150 毫秒窗口换好。
  - 页面能从本地文件地址解码并播放视频（临时放了一个隐藏的 `<video>` 读完即删）。
  - `data-testid="chat-view"` 在这个版本的页面上不存在，会话区的标记是 `data-testid="conversation"`。
- **启动器程序，2026-11-27**：
  - Windows：`setup-launcher.mjs` 在本机真实编译出 `ZCode Appearance.exe`（38 KB，图标和编译一共约 2 秒），图标取自 `D:\Program Files\ZCode\resources\icon_windows.png`，Windows 能从 exe 里把图标读回来；程序以脚本的路径、脚本所在的目录和 `ZCODE_APPEARANCE_NO_CONSOLE=1` 拉起 node；没有 node、找不到脚本时退出码 1 并写下日志。找 ZCode 的三种来源在本机都对上了：登记表里的卸载条目给出安装目录，正在运行的进程给出同一个路径。
  - macOS 与 Linux：**没有实机**。`.app` 包的结构、`Info.plist` 的转义、`.desktop` 的转义，是把平台切换后在本机生成并核对的；桩脚本在 Git Bash 的 `sh` 下按两种布局真实跑过（拉起 node、找不到路径文件、没有 node、用 `ZCODE_APPEARANCE_NODE` 指定）。没有验证过的：`sips` 转 `.icns` 的回退（只在 `ZCode.app` 里找不到 `.icns` 时才会用到）、macOS 的 `display alert` 提示、Linux 的 `zenity` / `notify-send` 提示、程序坞和应用列表里的实际显示。
- **面板在真机上（2026-11-27 晚，Windows，安装后）**：侧边栏「扩展」里出现「外观」，点开能画出全部控件，状态行读到「启动器在运行」。第一次看到的是英文：宿主给扩展的 `env.get()` 是一次异步调用，扩展却按同步去读结果，读到空值就落到了英文（测试里的假宿主写成了同步，所以没拦住）。已改成等待它的回答，假宿主也改成异步，并补了「中文 → 改成英文 → 下一次回答跟着变、问不到时是英文」的用例；改回去会被 9 个用例抓住。完全重启之后是中文了。
- **独立审查（2026-11-27 晚，`reviewer` + `guard`，针对提交 `9d48500`）**：没有 P0。按发现修掉的：`--uninstall` 会删掉 `--dir` 里别人的文件（现在只往专用目录里写、只删自己的文件）；样式会送进从网络地址加载的页面（现在只跟非 http / https 的页面打交道，测试页面也改成了 `file:` 地址）；等不到 `#root` 的窗口每 10 秒被重发一次整份样式；媒体路径接受网络路径；`rotateMinutes` 没有上限（超过定时器能等的长度就变成每毫秒触发）；`--attach` 的「一分钟无应答退出」实际约两分钟；几处小的（`remove` 对不在列表里的路径也说成功、`pick` 清掉还没被读走的提示、连接超时后的 socket、`--copy` 对别人的 `app/` 目录、`.desktop` 的转义）；系统工具（PowerShell、cmd）改为按完整路径启动。每处修复都有用例，把修复改回去会被对应用例抓住（UNC 的两道检查在 Windows 上互为备份，去掉解析前的那道在本机测不出来，它管的是 macOS / Linux）。没改的：审查里的几条风格 nit。后来改的：查找顺序里常见目录排到了登记表前面（启动提速，见上）。

- **没有在真机上试过的**：新的六套皮肤和「自定义」预设的实际观感、文件列表的拖动排序与「显示这一项」在真实面板里的手感（这三样都在无头浏览器的面板测试里逐个控件操作过）、系统的文件选择框、系统取色窗口、模糊、浅色主题、多个轮换、macOS 与 Linux。

## 卸载

在 ZCode 里停用或卸载本插件；删除文件夹 `~/.zcode/appearance/`；做过启动器程序的话运行一次 `node bin/setup-launcher.mjs --uninstall`；用原来的快捷方式启动 ZCode 即回到原版。
